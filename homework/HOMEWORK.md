# HOMEWORK: Observability

Практика после лекции: своё Spring Boot приложение, PostgreSQL, Prometheus, Grafana и нагрузка k6. Готовые PromQL и подсказки по стенду - в [ANSWERS.md](ANSWERS.md). Ничего сдавать не нужно.

Клиент: браузер (Grafana / Prometheus UI), терминал (Docker, Maven, k6).

---

## 1. Стенд и приложение

- [ ] Поднимите **PostgreSQL** (локально или в контейнере)
- [ ] Напишите **Spring Boot** приложение, которое ходит в эту базу (минимум один HTTP-эндпоинт с чтением или записью в БД)
- [ ] Подключите **Micrometer + Actuator**: endpoint `/actuator/prometheus`
- [ ] Поднимите **Prometheus** и настройте scrape приложения
- [ ] Поднимите **postgres_exporter**, подключите к вашей БД, добавьте job в Prometheus
- [ ] Поднимите **Node Exporter** (хост или контейнер с Linux-метриками), добавьте job в Prometheus
- [ ] Поднимите **Grafana**, datasource = Prometheus
- [ ] В Prometheus → **Status → Targets**: приложение, postgres_exporter и node_exporter в состоянии **UP**

---

## 2. Дашборд Grafana - руками

Создайте дашборд **вручную** (не импорт готового JSON). Три секции панелей.

### Приложение (метрики Spring / Micrometer)

- [ ] **Heap** - используемая heap-память JVM
- [ ] **Non-heap** - используемая non-heap память JVM
- [ ] **HTTP-статусы** - на **одном** графике серии для ответов **200 / 300 / 400 / 500** (или семейств `2xx` / `3xx` / `4xx` / `5xx`)
- [ ] **Пул соединений к БД** - активные и неактивные (idle) соединения
- [ ] **Потоки** - количество потоков JVM
- [ ] **RPS приложения** - запросов в секунду

### База данных (метрики postgres_exporter)

- [ ] **RPS базы** - запросов (или транзакций) в секунду
- [ ] **Долгие транзакции** - количество транзакций, открытых **дольше одной минуты**

### Linux (метрики Node Exporter)

- [ ] **Оперативная память**
- [ ] **CPU**
- [ ] **Память диска** (свободная / занятая на файловой системе)
- [ ] **I/O wait** - процент времени CPU в ожидании завершения операций ввода-вывода

---

## 3. Нагрузка k6

- [ ] Установите k6 (если ещё нет)
- [ ] Напишите скрипт, который бьёт в ваш HTTP-эндпоинт (достаточно smoke или короткого load)
- [ ] Запустите нагрузку и убедитесь, что панели дашборда **шевелятся** (RPS, статусы, пул, CPU и т.д.)
- [ ] (Опционально) пуш метрик k6 в Prometheus через `experimental-prometheus-rw` - как на лекции в `demo/`

---

## Критерий «готово»

Все Targets UP, дашборд собран руками, под нагрузкой k6 видно изменение метрик приложения, БД и хоста.
